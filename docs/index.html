One fact, one home

These pages deliberately do not repeat each other. The two-door trust model is argued once, in Architecture; how a packet travels is traced once, in Networking; the list of what does not work yet lives once, in the Operating manual. Where a page needs a fact that belongs somewhere else, it links rather than restates.

The system in one screen

Seven containers defined by a single docker-compose.yml. Which network interface a service listens on is what decides who can reach it — that is the whole access-control design, and Architecture §02 explains why it is done that way rather than with a firewall.

03

Reading these three ways

In a browser — the full version, with diagrams

Caddy serves this directory on port 8446, bound to 127.0.0.1 only. The single way in is an SSH tunnel, which means no extra network exposure at all — not to the house, not even to the tailnet: 

ssh -L 8446:localhost:8446 homie-lan
# then open http://localhost:8446

In a terminal over SSH — text, no diagrams

bin/homie-docs renders any page as plain text. It strips the SVG diagrams, so the wiring diagram in particular is worth a browser. 

homie-docs                  # list what is here
homie-docs manual           # prefix match
homie-docs --search vpn     # grep every page at once

As files

Everything here is committed to the repo. The two .md files are working notes and read fine in any editor; the four .html pages share homie.css, so open them through the server rather than as file:// if you want them styled.

Keeping these honest

Claims here are checked against the running machine rather than against the plan that produced it — bin/homie-check is the instrument, and it is what these pages were re-verified with. Numbers that drift daily (library size, free space, item counts) are deliberately not quoted anywhere in the set; ask homie-check instead.
